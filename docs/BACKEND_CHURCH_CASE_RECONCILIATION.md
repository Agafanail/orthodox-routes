# Reviewed reconciliation of a pending administration case

A final administrator can resolve the page through a separate legitimate membership lifecycle while a support case remains pending. That does not mean its earlier protected replacement/archival command executed. This slice adds a metadata-only reconciliation using the existing separate church operator, safe preview, 15-minute hashed capability, explicit confirmation, committed attempt, immutable outcome lookup and minimized audit. It never assigns/ends a position, changes church visibility, sends another notification, or authorizes personal deletion.

Use the fixed action `reconcile_church_administration_case` with `--church`, `--administration-case` and the matching opaque `--case` reference. It accepts no replacement, membership, invitation or `--support-deletion` input. Preview is the default; `--execute` retains the exact interactive operation confirmation. The current target membership must already be ended. Either an accepted current administrator must cover the page or the page must already be archived. A still-occupied final position or an uncovered published page cannot be reconciled. No email/account discovery is introduced.

Preparation derives safe public references and current counts, while an ungranted fingerprint pins the complete restricted case, selected membership and native church state. Execution retains native login/token/expiry/fingerprint and church slot/church/operation locks. The additional case row lock is followed by fresh deadline and fingerprint checks; a read-only row-lock wait cannot extend confirmation. A late failure rolls back only case/audit/operation effects together, preserving the separately committed attempt. Finished retries return their original outcome without rerunning reconciliation. Concurrent prepared candidates can produce only one successful metadata transition.

`resolution_source` distinguishes `owner_transition` from `observed_membership`. Existing case resolutions retain their actual native-transition source. Reconciliation records its own prepared/executed operation, the observed replacement/archive result and no invented replacement membership. The earlier protected command remains unchanged and is never marked successful. Audit uses fixed `church.administration_case_reconciled` / `reviewed_administration_reconciliation` and only `administration_case` as the changed field. Case, account/contact/Auth, membership, church, transport and notification boundaries remain protected; the only intended changes are restricted case and correlated operation/audit metadata. No domain notification or provider call is added.

The owner command checks exact case/membership/resolution references and projects recognized fields only. Ordinary/service roles cannot call reconciliation or read its table; the operator can call only the fixed preparation and existing audited execution, never the transition/fingerprint helpers. There is no new role, production access, scheduler or ordinary application endpoint.

Required disposable SQL verification exercises actual actor-bound invitation creation/acceptance with own-seat transfer and a real voluntary exit on an archived page. Token material is read only from the protected synthetic mail fixture in memory, never printed; this is not mailbox/provider or real representative verification. Tests also cover an occupied position, wrong targets/references/roles/operator/token, ordinary and post-case-lock expiry, changed-case freshness, late rollback, immutable failures, competing successful/refused execution, original-command preservation, unchanged private/domain/notification fingerprints, archive observation and ACL/replay. Command tests use injected process/confirmation fakes. Required SQL/full CI remains pending until recorded in the campaign.

Initial CI `41030241766` passed the other three jobs and the upgraded native case verifier, then exercised actual transfer, expiry/case-row wait, rollback, concurrent observed replacement and unchanged domain checks. It failed at the test helper reading the voluntary-exit boolean: `psql` emitted `t`, which is not JSON. The helper now explicitly projects `to_jsonb` for both JSON and boolean RPC results. No domain/authorization rule was changed; corrected full CI remains required for archive reconciliation and complete replay proof.

The earlier case migration and this forward patch are replayed in order: the latter restores the current completion dispatcher after the earlier source definition. This is composed upgrade proof rather than a claim that replaying an old migration alone preserves every later function. Earlier support intake/confirmation, actual closure/revocation/anonymization/ledger, final deletion integration and operational activation remain unfinished. A historical resolved case alone is never permission to delete an account; that workflow must recheck current memberships and other authoritative facts.
