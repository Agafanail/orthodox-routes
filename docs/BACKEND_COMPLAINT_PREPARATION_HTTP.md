# Unregistered complaint preparation HTTP composition

`createComplaintPreparationController` composes the existing strict request reader,
verified reporter seam, encrypted retry codec and preparation broker. It is not
registered as an application route and has no default client, environment secret,
proxy trust rule or provider configuration. No received complaint or public form is
activated.

## Retain identity before an uncertain write

The browser supplies a new random per-form UUID in `x-complaint-preparation` and retains
that non-secret selector with its unsubmitted form. The selector gives no authority:
it is not the reporter, database client idempotency key, resume proof or email proof.
All actual intent values are independently generated by the existing server codec.

1. A same-origin JSON POST without that form's cookie establishes only encrypted
   server retry state and returns `state_required`/428. It makes no broker call,
   consumes no database budget/challenge and writes no draft. Only transport/selector
   validation has happened; this is not target/domain authorization.
2. A later request bearing the retained cookie may prepare. The current reporter and
   independently trusted network address are required; the real broker revalidates
   input, consumes a fresh budget, verifies a fresh fixed-action challenge, and calls
   the protected database operation. A cookie set only on the same uncertain write's
   response would not provide retry identity when that response was lost.
3. Explicit repeats use the same intent. Unknown/thrown/aborted outcomes, later budget
   denial or challenge rejection preserve the original identity without renewing it:
   an earlier attempt might already have committed. No automatic repeat is made.

The future interface can establish state before submission; this transport handshake
does not require a new user-facing consent or extra press. A lost bootstrap response
cannot have committed a draft. Retention/availability remains conditional on actual
browser cookie storage: eviction or deliberate removal is not exactly-once delivery.

## Cookie isolation and outcomes

Each form has its own `__Host-orthodox-routes-complaint-preparation-<UUID>` cookie.
It is Secure, HttpOnly, SameSite Strict, Path `/`, with no Domain. A purpose-specific
HMAC-derived per-form codec key binds ciphertext to the selector as well as the
existing reporter binding. Forms/tabs cannot overwrite one another's identity; a
transplanted ticket is refused. There is no one-complaint-per-browser product limit.

The original fifteen-minute unsubmitted-state ceiling is never extended. Successful
pending/verified draft results tighten it to the database expiry where earlier.
Cookie max-age rounds up only for transport seconds; the encrypted deadline is exact
and independently checked before every use. A cookie is neither a target authorization
nor a way to extend the database's reporting window.

| Outcome | HTTP | State handling |
| --- | --- | --- |
| `state_required` | 428 | Issue state only; no preparation |
| `state_invalid` | 409 | Clear only the selected invalid/expired/ambiguous cookie; no preparation |
| `pending_email`, `email_verified` | 200 | Minimal draft UUID/status/database expiry only; tighten existing lifetime |
| `expired` | 410 | Clear only the selected closed draft's cookie |
| `rate_limited`, `rejected` | 429, 400 | Preserve existing retry identity |
| `invalid_request`, `unavailable` | 400, 503 | No privileged work after refusal; preserve uncertain state |

Malformed clocks/configuration/receipts fail closed without discarding uncertain
identity. Cookie-store exceptions return only unavailable. Public responses are fixed
and private/no-store with no-referrer/nosniff; raw intent, actor, IP, mailbox, text,
target, challenge, provider errors and capabilities are never forwarded or logged.
No status says `received`.

## Bounds, verification and activation gaps

The existing body reader allows five seconds/64 KiB. The reporter seam has its own
bounded Auth/account reads; the controller also contains an ignored seam at twelve
seconds. The broker bounds budget/challenge/write individually; its outer wait is
sixteen seconds. A late/abandoned write remains an unknown commit outcome, not rollback.
These are defensive dependency bounds, not approved operational rate values or actual
hosting/load acceptance.

No-network tests use real codec/broker logic with fake framework cookies, RPC and
challenge. They cover lost bootstrap/receipt outcomes, fresh checks on repeat, two
concurrent forms, slot transplant refusal, authority separation, malformed metadata/
state/configuration/expiry, exact clearing, private errors, aborts and ignored waits.
They are not real Set-Cookie/browser/provider/proxy or combined database proof.

Before registration: provide verified hosting/proxy address acquisition (never a
leftmost-forwarded-header fallback), bind the actual per-request framework cookie jar
and reporter seam, provision dedicated secrets and approved operational limits,
complete explicit mailbox confirmation and resend, received cases, working owner
receipt/review, maintenance and approved retention. Then verify actual browser cookie
acceptance/multiple forms, provider/mailbox, disposable/staging SQL and hosting behavior.
No product/retention conflict or owner-controlled action is resolved by this controller.
