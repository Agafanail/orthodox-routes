# Restricted final-administrator support resolution

This inactive backend contract implements the reviewed replacement/archival part of IA 20.4, Backend Architecture section 15 and Target Data Model section 13.7. It reuses the existing separately authenticated church operator, prepare/execute capabilities, committed attempt audit and fixed command. It does not activate an operator, accept a public support request, confirm or execute account deletion, revoke sessions, or establish retention.

An owner must first review a real support-assisted deletion request and identify the exact public church/membership references and, for replacement, the incoming confirmed representative's public account reference. No discovery by contact, domain or account identity is provided. Add `--support-deletion` to `replace_church_admin` or `archive_church`; either decision requires `--membership`. Replacement still requires `--replacement`. All other actions reject this flag. Connection, logging, preview-only default, exact interactive confirmation, committed attempt and own-operation outcome rules remain those of [the fixed owner command](BACKEND_OWNER_COMMAND.md).

The two fixed preparation wrappers delegate to the existing native preparation and bind its operation to one forced-RLS `ops.church_administration_case`. The selected membership must be the final current position and have no unresolved pending transfer. Only a reviewed case reference, fixed deletion reason, internal relationships, operator fingerprint, decision and operation/timing facts are stored. No contact, narrative, capability or private transport payload enters the case. Application/service roles and the operator itself have no direct table access; the case is not exposed through the Data API or ordinary UI/export. Its internal states are never ordinary-user copy.

Preparation records restricted operational metadata only: it preserves the last position, church visibility, identity and rides. A fully valid preview produces `replacement_pending` or `archive_pending`, retaining the same case on a fresh preview for the same membership/reference. A different reference is refused for review. A new preview supersedes the case's prior pending decision: its old capability cannot commit, even if the church fingerprint has not changed. Expiry/failure leaves the case pending; a fresh review/preparation is required, never an automatic retry.

Execution retains the native login/token/expiry/fingerprint checks and church slot/church/operation lock order. Replacement keeps the existing confirmed-user factor locks and swaps the exact seat without transferring identity/history. Archival retains every existing future-transport refusal; it never cancels other people's trips. After allowed archival, the selected final membership ends. A protected trigger completes the linked case and minimized case audit inside the same inner transaction as domain success. Any late error rolls back church/membership/case/notification/domain audit changes together, leaving only the separately committed attempt outcome. Successful native first-call and replay results retain their existing shapes. The command projects the bound case UUID from the validated preview alongside that native success; it prints no capability or unrecognized fields.

Replacement retains the existing neutral six-language notification. Archival uses the same prepared reviewed-membership-change copy, excludes case/account/contact data, and links to the existing church/catalog route within its bound. Preferences and provider dispatch remain unchanged. Case opening/resolution adds fixed minimized operator facts, never free text or private before/after values. Retention is not activated.

Actual local-only Docker verification in required CI covers role/table/helper isolation, safe preview, final-seat refusal, preserved private/transport data, wrong operator/token/reference, superseded decisions, late rollback after a real seat swap, immutable failed replay, simultaneous successful replay, case/audit correlation, future-work archival refusal, final membership closure, and migration/ACL/constraint replay. Local command tests use injected connection/confirmation fakes; neither proves operational authentication, TLS, representative review or production readiness. Local Docker remains unavailable on the owner workstation.

Remaining deletion work includes verified intake/confirmation, earlier `needs_administrator` intake and pending-case reconciliation when a separate legitimate membership lifecycle resolves the page, actual closure/revocation/anonymization/ledger, and the integration that resumes personal deletion from current membership facts. Pending case metadata is not itself permission to delete or a new block on voluntary administration changes. Production activation and legally approved retention remain separate.
