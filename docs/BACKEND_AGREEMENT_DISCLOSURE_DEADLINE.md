# Agreement confirmation disclosure deadline

The immutable accepted conditions bound contact/exact-data access to no later than thirty days after their scheduled arrival. Initial confirmation previously used only the driver's occurrence arrival for its contact/deletion deadlines, while the relationship guard correctly enforced the accepted snapshot's scheduled arrival. Distinct requested/offered arrival times could therefore make an otherwise permitted manual confirmation fail with a constraint error.

PR #98 CI `41043787717` exposed this in the unchanged browser scenario: separate wall-clock form fills crossed a minute boundary, with the offered arrival one minute later than the requested arrival. The UI reported a failed action at confirmation. Verify, database-foundation, local-auth and all cleanup passed; core-browser-e2e failed. This is a backend confirmation defect, not evidence that the new mail sender executed or exposed contacts.

The correction clamps the existing confirmation deadline to the earlier of the occurrence and accepted snapshot arrival, plus thirty days. It never extends a previously valid deadline. Agreement, exact-data and both contact snapshots receive the same clamped instant. Accepted conditions, transport eligibility, matching rules, capacity, disclosure authorization, cancellation and historical rows remain unchanged. The relationship guard is preserved rather than weakened.

The guarded migration replaces only the initial confirmation deadline assignment through the installed function definition, preserving signature, mode, grants, account fencing and remaining transaction/idempotency logic. Missing/unexpected definition shape fails closed; actual replay compares the definition, ACL and function mode.

The disposable agreement verifier deliberately uses a driver one minute later for the first full confirmation, and one minute earlier for the existing lifecycle boundary fixture. It checks successful actual authenticated confirmation, the exact minimum deadline in agreement/contact rows, same-key replay, unauthorized access and the existing cancellation/expiry/archival regressions. Equal-arrival concurrent confirmation remains covered. Real database/browser execution is required in CI; unavailable local Docker is not replaced by source assertions. No provider, retention setting, dependency or production operation is introduced.
