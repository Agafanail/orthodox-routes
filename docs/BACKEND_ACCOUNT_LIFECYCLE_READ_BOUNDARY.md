The guarded forward migration adds the negative `deleting`/`deleted` check to the existing ungranted `app.current_actor_id()` helper. The established `current_eligibility` diagnostic remains available to the same authenticated subject in every standing, returning the existing false eligibility/state/factor-reason summary, never profile, contacts or transport data. Its wrapper derives that subject directly from Auth, with the original null-subject refusal retained. It does not authorize a private read or mutation. Initial corrected CI `40858162569` exposed this compatibility requirement before the new boundary verifier ran; the existing foundation assertions are preserved, not weakened.

Restricted standing is different from deletion. Real HTTP checks preserve those reads and restricted cancellation, while the existing positive account/eligibility fence still rejects republication. Original synthetic standing/timestamps are restored in `finally`; failed assertions compare booleans rather than private response bodies. Migration/ACL and helper-mode replay are checked separately.

This is deletion-read authorization preparation only.
