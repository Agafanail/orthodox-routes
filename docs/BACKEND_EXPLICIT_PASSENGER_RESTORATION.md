# Explicit passenger restoration

IA V2 sections 14.2 and 48.1 require a fulfilled request to stay non-public after a driver cancels. The September automatic-republication migration contradicted that approved behavior; it is implementation history, not a product amendment. The forward migration removes only that branch from the existing cancellation helper. It does not rewrite historical active requests whose authors' intent cannot be established.

Cancellation of an agreement, a whole occurrence or a series returns seats once and moves a fulfilled request to `restore` (or `expired` when its requested time has passed), irrespective of the cancelling participant. Further cancellations keep a hidden request hidden. An already active/partial group's unmet need still increases automatically. Other confirmed agreements and their authorized disclosure remain intact; cancelled agreements never regain contact or exact-place access.

The existing authenticated author-only `restore_passenger_request` explicitly republishes the same request, with its existing eligibility/channel/account fence, deadline, remaining-need and idempotency checks. The existing author cancellation supports refusing restoration without cancelling another confirmed agreement. No new mutation, grant, provider, dependency, policy value or table is introduced.

The configured Core board reuses the existing author-only `current_transport_items` projection. Only church name and the original service-name snapshot are added to that private projection; it already contains the author's own exact places and conditions. `Снова искать поездку` opens a read-only review of church/service, requested arrival/timezone, total/remaining passengers, children, seat/return requirements, original meeting addresses and note. Opening it does not publish. A separate `Опубликовать снова` form performs publication; `Больше не искать поездку` refuses it. Incomplete review data removes the publication action, not the refusal action. This is minimal integration of the approved backend transition, not a production design-system migration or a general listing editor.

Verification covers non-public driver cancellation, author-only review and restoration, unchanged original conditions/identity, idempotent replay, expiry/refusal, partial groups and surviving commitments, whole-occurrence/series cancellation, closed disclosure after republication, migration replay and retained ACL. The existing browser regression now cancels as the driver, opens the passenger's old conditions on desktop/mobile, proves review alone leaves the public list empty, explicitly publishes, and rechecks disclosure. The staging smoke expects the same transition but is not evidence of a remote run until executed against an owner-available isolated staging environment. Local Docker unavailability must not be described as local SQL/browser integration success; disposable CI provides that proof.
